# Spec: the image of the group `bayes` — CmdStan and its toolchain (`bayes-image`)

Status: **approved by the owner on 2026-11-23.** It specifies the module `bayes-image` of the
capability map `docs/specs/bayesian-editor-map.md` (**the map**), step 0 of its order of construction
(«measure first»). It holds the measurements the map asked for before any spec («Measured on 2026-11-23»),
the recipe proposed, the self-test, the administration card and the risks. The modules that use the image
— `stan-compile` (the compile Job and the cache of binaries) and `bayes-runner` (the sampling Job) — have
specs of their own; this one gives them numbers and the contract of the image, and decides nothing that is
theirs.

It reuses the architecture of `docs/specs/statistical-models.md` (**the models spec**) and does not repeat
it: a group's recipe pinned by version and by sha256 («The supply chain»), the image built in the cluster
by the scripting machinery when an administrator enables the group, the check Job (lock, then self-test,
uid 10001, read-only root, no network), `RecipeHash` and `RunnerHash`, the card in **Administration →
Statistical models**. The nearest precedent is the group `foundation_forecast`
(`docs/specs/foundation-forecast.md`): a Python group whose recipe pins, besides its packages, files by URL
and sha256 (`wheels`, `weights`).

The owner's answers this spec rests on (the map, «The owner's decisions», and the interview of
2026-11-23): the runner is **Python**; a model is **compiled in the background when a version is saved**,
the run compiling only as a fallback; the compiled binaries are kept in a **least-recently-used cache whose
limit the administrator sees and sets**; **NUTS only**; **every limit is a setting with its default
visible**.

## Decisions (2026-11-23)

The first draft's four open questions, answered the same day.

| Question | Decision | By |
|---|---|---|
| The precompiled header in the image | **Kept**: the image is 1.90 GB, a compile 11–28 s on the measured CPU (21–38 s without it) | Owner |
| CmdStan's build parallelism | **`-j1` always** (`"jobs": 1` in the recipe): it fits the default 4 GiB build Pod (266.5 s, no OOM); `-j2` was OOM-killed there | Owner |

## Objective

An administrator enables the group `bayes`; the cluster builds an image that holds CmdStan, built once with
its precompiled header and its threading support, the C++ toolchain that compiles Stan programs, and the
Python packages of the runner, every byte pinned. The image then serves two kinds of Job with one contract:
a **compile Job** (a Stan program generated by Tabularia → an executable in `/tmp`) and a **sampling Job**
(the executable, checked by its sha256, run with NUTS), both as uid 10001 with a read-only root, `/tmp`
the only writable path, no network. The administrator sees what the image holds, sets its resources and the
limits of a compile, and sees and sets the size of the cache of binaries.

Who it serves: the administrator (enables, sizes, watches the cache); `stan-compile` and `bayes-runner`
(they rely on the contract of the image: paths, flags, what is writable, what a compile costs).

### Compiling three typical programs

The programs, written by hand as `stan-codegen` would generate them: a **linear regression** (`N`×`K`
design matrix, `normal` likelihood, 5 parameters); a **hierarchical logistic regression with correlated
varying intercepts and slopes** (20 groups, `cholesky_factor_corr` with an `lkj_corr_cholesky(2)` prior,
non-centred: `beta = rep_matrix(mu', J) + (diag_pre_multiply(tau, L_Omega) * z)'`, the correlation matrix in
`generated quantities`; 48 parameters); an **AR(1)** (3 parameters). Each compile ran with `make
/tmp/m/<name>` in `/opt/cmdstan`, the image's flags (`STAN_THREADS=true` from `make/local`, CmdStan's
default `-O3`), as uid 10001, with the dependency files generated at build («What fails, and its cure»),
and `PRECOMPILED_HEADERS=true` on make's command line. The contract below passes `false` instead; GCC used
the header in that configuration too (the `-H` line), but its clean times were not measured separately.

| Program | With the precompiled header | Without (the header hidden) | Binary |
|---|---|---|---|
| Linear regression | **12.5 s**, 1,368 MiB peak RSS | 23.1 s, 1,598 MiB | 2,537,520 bytes |
| Hierarchical logistic, LKJ, non-centred | **27.7 s**, 1,862 MiB | 38.1 s, 1,917 MiB | 2,812,480 bytes |
| AR(1) | **10.8 s**, 1,301 MiB | 20.9 s, 1,532 MiB | 2,501,552 bytes |

- The precompiled header saves **about 10 s a compile** (40–50 % for the small programs, 27 % for the
  hierarchical one). The peak RSS with it counts the header's 954 MB mapped from the image; the cgroup's
  peak of the strict runs below was 713, 782 and 1,257 MiB with the header, 1,524 to 1,912 MiB without.
- **A compile is one process at a time**: CPU time ≈ wall time (for example 26.5 s user for 27.7 s). More
  than one CPU does not make a compile faster.
- **GCC uses the precompiled header by itself.** CmdStan 2.40's makefile passes `-include-pch` only for
  clang (`make/program`); with GCC the header is found because the generated C++ includes
  `stan/model/model_header.hpp` first and the `.gch` directory sits beside it. Measured with `-H`: the line
  `! stan/src/stan/model/model_header.hpp.gch/model_header_threads_14_2.hpp.gch` (the header was used);
  hidden, the same compile takes 10 s more. A header built with other flags is silently not used (below).
- **`-O3` is CmdStan's default** (`O ?= 3` in Stan Math's `make/compiler_flags`); nothing to change.
  **`STAN_CPP_OPTIMS=true`** (extra GCC loop and vectorization flags): the hierarchical program compiled in
  **44.5 s** (1,827 MiB) — the header is *not* used, its flags differ — and sampled in 3.6 s against 3.8 s
  (the four chains' total, 7.48 s against 7.84 s: **about 5 % faster**), binary 3,062,928 bytes. Not worth
  it («Decisions»: off).
- **The same program gives the same bytes**: the AR(1) compiled in two containers of the image has the same
  sha256 (`7a3f2e71…4f1a`). `/tmp` held 2.5–3.0 MB after a compile (the program and the binary; make deletes
  the intermediate `.hpp` and `.o`).

### Read-only root, uid 10001, no network

Every compile above was also run as
`docker run --read-only --tmpfs /tmp:rw,exec,size=2g --user 10001:10001 --network none --cap-drop ALL
--security-opt no-new-privileges` (the model Job's isolation, verified in `internal/api/jobs_models.go`:
read-only root, uid and gid 10001, no capability, no ServiceAccount token, `/tmp` an `emptyDir`). Result:

- **It works.** The three programs compile and link with only `/tmp` writable and no network: `stanc`,
  `g++`, the main object, TBB and the precompiled header are all in the image already. Nothing is
  downloaded (CmdStan's makefile downloads `stanc` only when `bin/stanc` is missing; `make build` copied it).
- **What fails, and its cure.**
  1. `make build` does not leave the dependency files of the main object and of the precompiled header
     (`src/cmdstan/main_threads.d`, `…/model_header_threads_14_2.d`). Each compile then tries to write them
     in `/opt/cmdstan` and prints `fatal error: opening dependency file …: Read-only file system` twice;
     make ignores it (`-include`) and the compile succeeds, **3 to 7 s slower** (15.8, 30.8 and 13.7 s
     instead of 12.5, 27.7 and 10.8 s). **Cure, measured**: build the two files at image build
     (`make src/cmdstan/main_threads.d stan/src/stan/model/model_header.hpp.gch/model_header_threads_14_2.d`);
     then a compile as uid 10001 on a root-owned `/opt/cmdstan` prints no error and writes nothing there.
  2. If the precompiled header is missing and `PRECOMPILED_HEADERS` is left at its default (`true` on
     Linux), make tries to build it in `/opt/cmdstan` and fails (`mkdir: cannot create directory …`). The
     header must be built in the image, or every compile must pass `PRECOMPILED_HEADERS=false`.
  3. **Docker's default `--tmpfs` is `noexec`**: the compiled binary copied there cannot run
     (`/tmp/ar1: Permission denied`). With `--tmpfs /tmp:rw,exec` it runs. A Kubernetes `emptyDir` is not
     mounted `noexec` (**assumed**, from the Kubernetes documentation; the kind trial checks it, and a
     cluster whose policy mounts `emptyDir` with `noexec` cannot run the group: the self-test says so).

### The binary on another container

The three binaries, compiled in one container, were copied into **a new container of the same image** and
sampled there (strict flags as above, the binary copied to `/tmp`, its sha256 printed first): it works. In
another image (`python:3.14-slim` without CmdStan) it fails:
`error while loading shared libraries: libtbb.so.2: cannot open shared object file`. A binary is dynamically
linked to TBB by an `rpath` into `/opt/cmdstan/stan/lib/stan_math/lib/tbb/`, and to the image's
`libstdc++`: **a binary is valid only with the image that compiled it** (its digest belongs in the cache
key, as the map says).

### Sampling

The hierarchical logistic program on its small data (600 rows, 20 groups), **4 chains, 1,000 warm-up and
1,000 draws each, `num_threads=3`**, `--cpus 3`, in the strict container:

| Measure | Value |
|---|---|
| Wall time | **3.8 s** (9.1 s CPU); each chain 1.8–2.0 s (about 1.0 s warm-up, 0.9 s sampling) |
| Memory | **15 MiB** peak RSS; the container's cgroup peak 22 MiB |
| CSV | **1.02 MB a chain**, 4.1 MB in all; 99 columns (7 of the sampler, 92 of the model), 1,000 rows of draws: about **10.3 bytes a value** of text |

The linear regression (200 rows) and the AR(1) (300 points) took 0.2 s each, CSV 101 KB and 81 KB a chain
(12 and 10 columns). On these sizes sampling is negligible beside compiling: **the compile is the cost**,
which is why it happens at save and is cached.

## Tech stack

- **Base**: the scripting environments' `python:3.14-slim` (recipe `"base": "3.14"`, as `boosting` and
  `foundation_forecast`).
- **Toolchain**: `g++` and `make` from Debian's signed archive (`apt-get install --no-install-recommends`),
  their versions recorded in the lock as the R groups' system libraries are.
- **CmdStan 2.40.0**, from the release's tarball by URL and sha256 (one per machine: `x86_64`, `aarch64`),
  built once in the image in `/opt/cmdstan` with `STAN_THREADS=true`, its precompiled header and its two
  dependency files; owned by root, read-only at run time.
- **The runner's packages**: `numpy==2.5.5` and `pyarrow==26.0.1`, by hash (`--require-hashes`), nothing
  else. No `cmdstanpy` (the map: its readers load whole chains; the runner calls the executable itself).
- **The machinery**: `internal/modelgroups` (recipe, `RecipeHash`, `RunnerHash`, the check Job's script) and
  `internal/scriptimage` (the managed Python Dockerfile), extended as «Changes to the machinery» says.

- **`toolchain`**: Debian packages, installed from the base image's archive before anything else. It is the
  `system_libraries` of the R recipes under a name that says what it is; the machinery accepts it only for
  this purpose (a fixed allow-list in Go: `g++`, `make`), never from a user's input.
- **`sources`**: one tarball per machine, like `wheels`: the URL, the sha256, the machine. The Dockerfile
  picks the one of `TARGETARCH`. A mirror setting (`MODELS__SOURCES_BASE_URL`, empty: GitHub) replaces the
  host and keeps the path and the sha256, as `MODELS__WHEELS_BASE_URL` does.
- **`cmdstan`**: not a command but three switches the Go code turns into a fixed build step:
  `threads` writes `STAN_THREADS=true` into `make/local` (the runner runs the chains in one process with
  `num_threads`, which needs it); `precompiled_header` keeps CmdStan's default (kept: «Decisions»); `jobs` is
  make's `-j` for this step (**1**: `-j2` was killed in the default 4 GiB build Pod).
- **`compile`** and **`cache`**: the defaults of the administration card («The administration card»); the
  recipe holds them so that the card shows where a default comes from. Changing them in the card needs no
  build.
- The `pin` tool learns `sources`: it downloads each tarball, hashes it and refuses it unless the hash equals
  the digest the GitHub release publishes for that asset.

### The Dockerfile the machinery generates

```dockerfile
FROM python:3.14-slim
ENV PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1 PIP_DISABLE_PIP_VERSION_CHECK=1 PIP_NO_CACHE_DIR=1
RUN apt-get update && apt-get install -y --no-install-recommends g++ make && rm -rf /var/lib/apt/lists/* \
 && dpkg-query -W -f '${Package}@${Version}\n' g++ g++-14 make >> /opt/tabularia/system-libraries.txt
COPY <<'TABULARIA_PACKAGES' /opt/tabularia/requirements.txt
numpy==2.5.5 --hash=sha256:c489… --hash=sha256:cc6e…
pyarrow==26.0.1 --hash=sha256:0044… --hash=sha256:7ae4…
TABULARIA_PACKAGES
RUN pip download … --require-hashes … && pip install … --require-hashes --no-index … && pip check
# the source, checked by BuildKit, kept out of the image's layers
ARG TARGETARCH
FROM scratch AS cmdstan-amd64
ADD --checksum=sha256:26d21c97…a90c https://github.com/stan-dev/cmdstan/releases/download/v2.40.0/cmdstan-2.40.0.tar.gz /cmdstan.tar.gz
FROM scratch AS cmdstan-arm64
ADD --checksum=sha256:c31e9f45…aa63 https://github.com/stan-dev/cmdstan/releases/download/v2.40.0/cmdstan-2.40.0-linux-arm64.tar.gz /cmdstan.tar.gz
FROM cmdstan-${TARGETARCH} AS cmdstan-source
FROM <the stage above, with the toolchain and the packages>
RUN --mount=type=bind,from=cmdstan-source,target=/src \
    tar -xzf /src/cmdstan.tar.gz -C /opt && mv /opt/cmdstan-2.40.0 /opt/cmdstan && cd /opt/cmdstan \
 && rm -f bin/mac-stanc bin/windows-stanc \
 && printf 'STAN_THREADS=true\n' > make/local \
 && make -j1 build \
 && make src/cmdstan/main_threads.d \
 && for h in stan/src/stan/model/model_header.hpp.gch/*.hpp.gch; do make "${h%.hpp.gch}.d"; done \
 && echo "cmdstan@2.40.0 sha256:$(sha256sum /src/cmdstan.tar.gz | cut -d' ' -f1)" >> /opt/tabularia/package-sha256.txt
RUN useradd --uid 10001 --create-home --shell /usr/sbin/nologin tabularia
USER 10001
WORKDIR /home/tabularia
```

(The `…` stand for the full hashes of the recipe; the generated file holds them whole. The header's
dependency file is named after the header, as the makefile names it — `model_header_threads_14_2.d` with
GCC 14.2 — so the loop needs no version arithmetic; the self-test checks that both files exist.) The stage selection by
`TARGETARCH` and the `--mount=type=bind,from=` of a `scratch` stage are **assumed** to work in the cluster's
rootless BuildKit 0.33 (the spike used `ADD` then `rm`, which left the 47 MB tarball in a layer); lot B0
checks both, and the fallback is the spike's form, 47 MB larger.

## The contract of the image (what `stan-compile` and `bayes-runner` rely on)

- **CmdStan at `/opt/cmdstan`**, version in `/opt/cmdstan/makefile` and `bin/stanc --version`
  (`stanc3 v2.40.0 (Unix)`, measured). Owned by root; nothing there is written at run time.
- **The compile**: `make -C /opt/cmdstan /tmp/<dir>/<name>` with the program at `/tmp/<dir>/<name>.stan`,
  run with an **empty environment** except `PATH` (`env -i PATH=/usr/local/bin:/usr/bin:/bin`), so that no
  `CXXFLAGS`, `STANCFLAGS`, `CPPFLAGS` or `LDFLAGS` of the Pod reaches make; and with **no variable on the
  command line** except `PRECOMPILED_HEADERS=false`. That value only stops make from managing the header
  (it never tries to rebuild it in the read-only `/opt/cmdstan`, «What fails», 2); GCC still finds and uses
  it (measured with `-H` in exactly this configuration). The flags are therefore the image's alone
  (`STAN_THREADS` from `make/local`, `-O3`), the precompiled header matches them, and the cache key's «C++
  flags» is a constant of the image. `stanc` runs with no flag (no `--include-paths`, no
  `--allow-undefined`): its arguments are make's (`bin/stanc --o=<file>.hpp <file>.stan`, measured).
- **The binary**: valid only with the image's digest; dynamically linked to the image's TBB and
  `libstdc++`; 2.5–3.1 MB for the measured programs; byte-identical when the same program is compiled again
  on the same image.
- **Writable**: `/tmp` only, and it must allow executing files (`emptyDir`, not mounted `noexec`).
- **Network**: none, at compile and at run time.
- **Threads**: the binaries are built with `STAN_THREADS`; the sampler runs `num_chains` chains in one
  process with `num_threads` equal to the CPU limit.

## The self-test

The check Job of the models spec (lock, then `python -I -B runner/run.py --selftest`, uid 10001, read-only
root, `--network none` equivalent, 2.5 GB) runs, besides the common library's tests:

1. **The image is the recipe's**: `bin/stanc --version` says the recipe's version; the lock line of CmdStan
   carries the recipe's sha256 for the machine; `make/local` says `STAN_THREADS=true`; the precompiled
   header, its dependency file and the main object's dependency file exist.
2. **A compile in the Job's conditions**: the reference program `reference/programs/ar1.stan` (the AR(1)
   above) compiled into `/tmp` exactly as the contract says (`env -i`, fixed arguments), as uid 10001 on the
   read-only root; it must succeed and print no `Read-only file system` line. A second compile of the same
   program — the self-test's only exception to the fixed arguments — adds
   `CXXFLAGS_PROGRAM=-H -Wno-ignored-attributes` and must print the line `! …model_header…hpp.gch` (**the
   precompiled header was used**; `-H` does not invalidate it, measured). Times and peak memory are printed
   as facts in the log, never compared with a threshold.
3. **The binary runs from `/tmp`**: `info` prints `stan_version_major = 2`, `stan_version_minor = 40`; a
   cluster that mounts `/tmp` `noexec` fails here with a sentence that names the cause.
4. **NUTS gives the known answer**: the reference program
   `reference/programs/normal_known_sigma.stan` (a normal mean with a normal prior and a known standard
   deviation: a posterior in closed form) sampled on `reference/data/normal.json` with 4 chains, 1,000 +
   1,000, fixed seed, `num_threads` 2; the posterior mean and standard deviation are compared with the closed
   form at a tolerance of four Monte Carlo standard errors computed from the draws (a check of the image,
   not a verdict shown to a user), and the CSV's header has the columns the runner expects
   (`lp__`, `accept_stat__`, `stepsize__`, `treedepth__`, `n_leapfrog__`, `divergent__`, `energy__`, then
   the model's).
5. **The same seed gives the same draws**: the four CSVs of step 4 hashed and compared with
   `reference/expected.json` **only on x86-64** (the reference is computed on x86-64; on arm64 the check is
   skipped and says so: floating point differs).

The next three checks are the ones `docs/specs/bayes-distribution-catalog.md` (**the catalogue spec**,
«Testing strategy», «Handed to `bayes-image`», and «Every name of the "Stan" column») hands to this
self-test: they check Stan's side of the catalogue with the pinned CmdStan.

6. **The catalogue's names exist in the pinned Stan.** `reference/programs/catalog_names.stan` calls every
   name of the catalogue's «Stan» column (statement, `_lpdf`/`_lpmf`, `_rng`, `_lcdf`/`_lccdf` where the
   catalogue lists them, and `binomial_rng(N, inv_logit(alpha))` for the binomial-logit generator). It is
   **generated from `catalog.json` by a Go test and kept as a golden file** (the test fails when the
   catalogue changes and the file does not); the self-test runs `stanc --info` on it and compares the
   functions and distributions stanc reports with the catalogue's names. That `--info` lists them is
   **assumed** (the catalogue spec leaves the way to the lot); the fallback is `stanc` on the program alone,
   which fails on an unknown name.
7. **The catalogue's points against Stan's own functions.** The witness's points
   (`gateway-go/internal/bayescatalog/testdata/points.json`, written by `make_points.py` with SciPy outside
   Tabularia; the catalogue spec, «Commands») are copied byte for byte into
   `reference/data/points.json` (a Go test keeps the two equal). `reference/programs/catalog_points.stan`,
   run once with the `fixed_param` sampler (one iteration), evaluates in `generated quantities`, for every
   case of the file of `kind` `density` or `mass` (distribution, arguments, point), Stan's **`_lpdf`** (or
   **`_lpmf`** for a discrete case) and, where the case has one, **`_lcdf`** at that point; the cases of
   `kind` `marginal` (LKJ's correlation, a multivariate normal's component: the browser's marginals, not
   Stan's joint densities) are left to check 8 and to the catalogue's own suite, and the check says how many
   it left; the file's format is the one `make_points.py` documents in its header (format 1); the runner reads the values from the CSV and compares them with the
   witness's log-density and the log of its CDF. **Tolerances, declared**: the log-density within a relative
   1e-10 (absolute 1e-12 when the witness's value is within 1e-12 of zero), the log-CDF within a relative
   1e-8 — the catalogue's browser tolerances for the density, wider for Stan's CDFs, whose tails use other
   algorithms than SciPy's (**assumed**, the lot measures them); a case for which `points.json` writes a
   wider tolerance with its reason uses that one. Each failed case is named with its distribution,
   arguments, point, both values and the difference. This closes, on Stan's side, the parametrization traps
   the catalogue lists (rate against scale, the Student-t's location and scale, the half forms by bounds).
8. **LKJ's marginal against Stan's generator.** For one correlation r of a K×K correlation matrix with an
   LKJ(η) distribution, (r + 1)/2 ~ Beta(η − 1 + K/2, η − 1 + K/2) (Lewandowski, Kurowicka and Joe 2009; the
   catalogue's binding draws it that way and marks it «assumed, checked in `bayes-image`'s self-test»).
   `reference/programs/lkj_marginal.stan`, run with `fixed_param` and a fixed seed, draws
   `lkj_corr_cholesky_rng(K, eta)` for the cases (K, η) ∈ {2, 3, 5} × {0.5, 1, 2, 10}, 4,000 draws each,
   forms Ω = L·Lᵀ and writes, for the elements Ω[2,1] and Ω[K,1], the probability integral transform
   u = `beta_cdf((r + 1) / 2 | b, b)` with b = η − 1 + K/2 (Stan's `beta_cdf`, itself checked at the
   catalogue's points by check 7). The runner applies to each case's u a **one-sample Kolmogorov–Smirnov
   test against the uniform distribution** (the exact distribution of the statistic, written in Python
   with numpy; checked in the suite against SciPy's `kstwo` as a witness outside the image) and fails the
   check when a p-value is below the self-test's **alpha 0.001**, the alpha the catalogue's own suite uses;
   with the fixed seed the test is deterministic. The p-values are printed. **This is a test of the
   software's correctness, not a verdict of a report**: the self-test passes or fails the image, with its
   numerical tolerances and its alpha declared here; the statistical verdicts a user reads stay the
   report's, under the node's alpha (the rule of 2026-11-20).

Exit 0 when nothing failed, 4 otherwise; the card shows the report as for every group. The self-test
compiles five programs (the AR(1) twice, the normal model, `catalog_points.stan` and `lkj_marginal.stan`:
about 70–90 s with the header on the measured CPU, an estimate from the three measured compiles) and runs
`stanc --info` once, within the check Job's limits; the draws and points are small (24 × 4,000 values for
LKJ, a few hundred points).

## Code style

The Go side follows the machinery as it is: a recipe field is a typed struct, checked at load, turned into
Dockerfile text by a function that refuses anything that is not of its shape. For example, the source step,
in the style of `wheelSteps` (verified in `internal/scriptimage/scriptimage.go`):

```go
// sourceStages are the stages that download the recipe's sources, one a machine, each checked by BuildKit
// against its sha256 and kept out of the image's layers; the build step mounts the one of TARGETARCH.
func sourceStages(sources []Source) (string, error) {
	var sb strings.Builder
	for _, s := range sources {
		arch, ok := machines[s.Machine]
		if !ok {
			return "", ValueError(fmt.Sprintf("«%s» is not a machine a source is built for (x86_64 or aarch64)", s.Machine))
		}
		if !url.MatchString(s.URL) || strings.ContainsAny(s.URL, " #`$") {
			return "", ValueError(fmt.Sprintf("«%s» is not the address of a source", s.URL))
		}
		if !sha256Hex.MatchString(s.SHA256) {
			return "", ValueError(fmt.Sprintf("the sha256 of «%s» is not 64 hexadecimal digits", s.URL))
		}
		fmt.Fprintf(&sb, "FROM scratch AS %s-%s\nADD --checksum=sha256:%s %s /%s.tar.gz\n", s.Name, arch, s.SHA256, s.URL, s.Name)
	}
	return sb.String(), nil
}
```

## Testing strategy

- **Go, no Docker** (`internal/modelgroups`, `internal/scriptimage`, `cmd/modelgroup`): the recipe loads and
  passes `CheckHashes`; a source without a sha256, with a bad machine or with an http URL is refused; a
  toolchain name outside the allow-list is refused; the generated Dockerfile holds the two stages, the fixed
  CmdStan step with `-j1`, the dependency files, the lock line; **every other group's Dockerfile and recipe
  hash unchanged** (the existing test); `pin` on a fake release (same bytes twice, a digest that differs is
  refused); `reference/programs/catalog_names.stan` is what the catalogue generates (golden);
  `reference/data/points.json` equals `internal/bayescatalog/testdata/points.json` byte for byte.
- **Python, no Docker**: the runner's Kolmogorov–Smirnov p-value against SciPy's `kstwo` on a few fixed
  statistics (witness outside the image); the comparison of check 7 on a hand-made CSV with one value off by
  more than its tolerance fails and names the case.
- **The image, once, by hand, one heavy job at a time** (lot B0): the build in a 4 GiB, 2-CPU limit; the
  check Job's script on the image; the self-test's eight checks; a wrong source hash stops the build before
  anything compiles.
- **On kind** (the map's step 8, and the first lot of `stan-compile`): enable the group from the card, the
  build in the cluster's rootless BuildKit, the check Job, a compile Job and a sampling Job in the real
  Pods (`emptyDir` executable, the network policy), the card's figures.
- Development on small data only: the self-test's data are a few hundred rows.

## Boundaries

As in the models spec and the map, plus:

- **Always**: CmdStan only from a release tarball pinned by URL and sha256 per machine; `g++` and `make` only
  from the base image's archive; the compile with an empty environment and make's own flags; `/opt/cmdstan`
  read-only at run time; `-j1` (or the recipe's `jobs`) for CmdStan's build; the lock carries CmdStan's
  sha256; every limit on the card with its default visible.
- **Ask first**: another CmdStan version (a new recipe, a new build of every enabled `bayes`, and the
  catalogue's copy of Stan's reserved names checked against that version's manual, as the catalogue spec
  asks); turning the precompiled header off, `-j2`, `STAN_CPP_OPTIMS` or any other flag («Decisions»); any
  package beyond `numpy` and `pyarrow` in the image; another base image; a compiler other than Debian's GCC.
- **Never**: `cmdstanpy`, `cmdstanr` or any installer that downloads CmdStan or `stanc` at build or run
  time; building `stanc` from a git checkout; `-march=native` or any flag tied to the build machine; a user's
  text in the Dockerfile, `make/local`, `STANCFLAGS`, `CXXFLAGS` or make's command line; network in a compile
  or sampling Job; a binary run in an image other than the one that compiled it; another product's name in
  the documents; a licence paraphrased as if it were the licence.

## Success criteria

1. `go run ./cmd/modelgroup dockerfile bayes` prints a Dockerfile whose build, in a container limited to
   4 GiB and 2 CPUs, succeeds without an OOM kill, in under 10 minutes on the measured CPU.
2. The image holds `/opt/cmdstan` with `bin/stanc --version` = `stanc3 v2.40.0 (Unix)`, `make/local` with
   `STAN_THREADS=true`, the precompiled header and the two dependency files; its size is within 10 % of the
   measured 1.90 GB minus the tarball's 47 MB.
3. As uid 10001, read-only root, `/tmp` the only writable path, no network: the three programs of «Measured
   on 2026-11-23» compile without a `Read-only file system` line, with the precompiled header used (the `-H`
   line), in times within 25 % of the measured ones on the same machine.
4. A binary compiled in one Job runs in a new Job of the same image digest after its sha256 is checked, and
   fails with a clear error in any other image.
5. The self-test passes on x86-64 with its eight checks (the catalogue's names, its points within the declared
   tolerances, LKJ's marginal at alpha 0.001 included); a hand-made wrong CmdStan sha256 stops the build
   before `make` with BuildKit's checksum error.
6. arm64 is named as supported only once the build and the self-test have passed on an arm64 node
   («Decisions»).
7. The card shows CmdStan's version and sha256, the toolchain's versions, the sampling and compile limits
   with their defaults, and the cache's limit, use and count.
8. Every other group's Dockerfile and recipe hash are unchanged.

## Risks

| Risk | Where it bites | Answer |
|---|---|---|
| **A compiler in a Pod** | Any code reaching `make` is compiled and run | Only `stan-codegen`'s output is compiled (the map's «Security»); empty environment, fixed arguments; no network; uid 10001, read-only root, no capability |
